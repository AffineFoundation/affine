## 1. What goes live on 2026-09-03

### 1a. Private submissions (R2)

Today you publish your checkpoint on Hugging Face and reveal `affine1|<repo>|<revision>|<hotkey>` on chain. Everyone can download your weights.

From go-live, you upload your checkpoint to a **private bucket** instead. Nobody but the validator and the eval pod can read it. Only a model that **wins the crown** is ever made public.

The flow, in one command (`submit.py submit`) or step by step:

1. `submit.py hotkey` — make an **Ed25519** hotkey and register it on netuid 120.
2. `submit.py check <dir>` — pre-flight your checkpoint directory (architecture pin, size caps, no python files).
3. **activate** — commit `affine2|activate|<hotkey>|<ed25519 signature>` on chain.
4. **auth** — the validator answers by posting a sealed blob at `https://dash.affine.io/mailbox/v1/<registration_id>/generations/…`. The blob is public bytes, but it is a NaCl sealed box: only your Ed25519 hotkey can open it. Inside is a temporary R2 credential (valid 7 days) that can only touch your own prefix, plus the validator's signature.
5. **upload** — `submit.py upload` puts your files under `models/registrations/<registration_id>/` and writes a signed manifest (every file's sha256).
6. **ready** — commit `affine2|ready|<registration_id>|<manifest_sha256>`. The validator revokes your credential, verifies the manifest, and queues the duel.

Losers stay private and their prefix expires after 60 days. A crowned model is copied verbatim to `https://models.affine.io/models/sha256/<model_digest>/` with its signed manifest, so every verdict that changed the board stays replayable.

**The HF path retires at the same moment.** `hf_cutover_block` is set to the finney block at flip time. Any `affine1|…` reveal above that block is dropped at intake. HF entries that are already queued still duel.

### 1b. Corpus D served from data.affine.io

The turn corpus D that duels sample from moves host: `https://s3.hippius.com/affine-sn120/turns/**` → `https://data.affine.io/turns/**`.

Same manifest, same sha256, byte-identical files. Only the URL changes. Hippius stays readable for history. Details in section 4.

## 3. What you need to do (miners)

Before you submit again:

- **Get an Ed25519 hotkey.** `btcli` makes sr25519 hotkeys by default. An sr25519 key cannot open the sealed credential and its activate signature is rejected (`rejected_not_ed25519`). Use `submit.py hotkey` (prints the ss58 and "Ed25519 ✓"), then register it: `btcli subnets register --netuid 120 …`.
- **Pre-flight your checkpoint.** `submit.py check <dir>` runs the same admission checks the validator runs (architecture pin, size caps, file hygiene).
- **Stop pushing to Hugging Face for Affine.** After the flip, HF reveals are ignored.
- **Update download scripts** that read D from Hippius: point them at `https://data.affine.io/turns/…` (section 4).

If you are already in the queue on the HF path, nothing to do; your entry duels as scheduled.

Full checklist with copy-paste commands: https://affine.io/llms.txt (section "Submit checklist"). The exact code that handles activate/ready is published at `code/affine/registrations.py`; the wire format at `code/affine/r2protocol.py`.

## 4. Corpus D moves to data.affine.io

- Pointer: `https://data.affine.io/turns/manifest.json` (schema 2, `corpus_epoch` 13, 59,745 turns).
- Immutable revision: `https://data.affine.io/turns/manifests/<sha256>.json`.
- Index: `https://data.affine.io/turns/index/turns_0013.parquet`.
- Chunks: `https://data.affine.io/turns/chunks/…`.

Every object is byte-identical to the Hippius copy; verify by hashing the manifest you fetch and finding it under `manifests/`. Verdicts stamp `corpus_base_url`, so a replay knows which host served the slice.

One known quirk: Cloudflare rejects the `Python-urllib` user agent on this host (HTTP 403). `httpx`, `requests`, `aiohttp`, `boto3`, `curl`, and browsers all work. If you use raw `urllib`, set a `User-Agent` header.

The **raw rollout traces** behind D are also public now: `https://data.affine.io/traces/manifest.json` lists every trace chunk (25k+ rollouts, `affine-traces-v1` envelopes). D is derived from these by the fold on the validator box; from 2026-09-04 the fold publishes a schema-3 view (`corpus/manifest.json`), see section 6.

## 5. Data generation: 3x fleet, teacher-only

Informational — none of this touches the contract.

- **Three datagen pods** now generate rollouts instead of one. Each pod owns a disjoint third of the task pool (hash of the task id mod 3), and all three publish into the same trace manifest (union merge). Throughput went from ~300 to ~900 rollouts/hour on single-turn tasks.
- **Teacher-only agent seat.** Since 2026-09-02 every new rollout is written by the duel teacher `Qwen/Qwen3.8-27B` itself (the GLM seat is switched off). New prefixes in D are therefore the teacher's own history, which keeps its duel-time reference thoughts on-policy. Existing GLM-written turns stay in the corpus.
- **Three harnesses** on the coding/terminal sources: mini-swe text (```bash fences), verifiers' `bash` tool harness, and `pi` (tool calls). The tool-call ones only enter D once `tool_call` is admitted on 2026-09-04.

Current trace corpus by assistant turns: coding 65%, terminal 30%, math 2.3%, nl2repo 1.6%, tool_use 1.0%. Python is 68% of coding turns; go, java, js, ts, cpp, rust make up most of the rest.

## 6. What follows on 2026-09-04 (wvk 11)

Noticed on 2026-09-02 as "not before 2026-09-09". **Date change (2026-09-03):** the operator moved T0 forward to **2026-09-04, 18:00 UTC (14:00 US Eastern)**. The content of the fork is unchanged; only the date moved. Effective on an explicit dated operator directive:

- `allowed_action_kinds` widens from `["bash"]` to `["bash", "tool_call", "boxed"]`. Turns whose action is a `<tool_call>…</tool_call>` block or a `\boxed{…}` answer enter D. On those turns a miner must emit that dialect or forfeits the turn (a forfeited turn is dropped from pairing, not counted as a loss).
- D becomes a **schema-3 view** over the public traces (`https://data.affine.io/corpus/manifest.json`, `duel_turns@v4`), target mix coding 0.50 / terminal 0.25 / math 0.10 / tool_use 0.10 / nl2repo 0.05.
- **D is rebuilt from the traces alone.** The pre-fork turns (epochs 1–13: python-heavy, generated under the previous teacher) are not carried into the new slice population. They stay byte-identical at `data.affine.io/turns/**` so every published verdict still replays. The schema-3 epoch 14 is already built (visible at the URL above; nothing reads it until T0): about 189k turns from 14.2k rollouts in 7.4k slice strata.
- **What a duel slice looks like from T0** (measured on epoch 14, n = 1300, three seeds): by group coding ≈ 56 %, terminal ≈ 27 %, math ≈ 11 %, tool_use ≈ 4 %, nl2repo ≈ 1 %. By dialect **bash ≈ 64 %, `<tool_call>` ≈ 24 %, `\boxed{}` ≈ 11 %**. The `tool_call` share is larger than the wiki source alone because coding tasks are also generated under two tool-calling harnesses (pi and the native bash tool). Coding languages: python 32 %, go 26 %, java 18 %, ts/js 17 %, rust/c 7 %. The fold enforces the mix on slice strata (what a duel samples), so these shares hold as D grows; tool_use stays below its 10 % target until a second tool source exists (the wiki set has 478 tasks).
- `weight_version_key` → 11. Forward-only: the reign stands, no genesis reset, `min_submission_block` unchanged.

R, G, B, the centering, the band, and the crown rule do not change; only the action parser is pluggable.

## 7. FAQ

**Why Ed25519 and not sr25519?** The mailbox blob is a NaCl sealed box addressed to your hotkey. `bittensor.Keypair.encrypt/decrypt` only supports ed25519 keypairs (it raises "encrypt/decrypt is only supported for ed25519 keypairs"). The blob must be openable by your hotkey and nobody else, so the hotkey has to be Ed25519.

**Are models private forever?** Losers, yes: never published, prefix expires after 60 days. A crowned model is published so anyone can replay the verdict that put it on the throne (two checkpoints + public D + `affine/score.py` recompute the result). Keeping kings private would break replayability; that is a policy decision, not a code toggle.

**Does my queued HF entry still count?** Yes. Only reveals above `hf_cutover_block` are dropped.

**Is the score different on the new host?** No. Same bytes, same slice, same rule.

**Do I need to change anything for 2026-09-04?** Only if you want to score on the new turns: your model must answer math turns with `\boxed{…}` and tool turns with `<tool_call>…</tool_call>` where the prompt's system message asks for it.
