# Live MATH launch and sustained learning

The operator authorized live SN120 reward cutover on October 3, 2026. This
supersedes the earlier restriction to proposed weights. Model execution nodes
still receive no chain-signing keys; one local payout writer owns chain writes.
Historical nonpayable epochs remain nonpayable and cannot be relabeled for payout.

## Acceptance gates

1. Freeze and admit a new source incorporating bounded audits and typed invalid
   sample comparisons. Preserve all existing source, checkpoint and audit history.
   Use the qualified learned successor 94ae9c68…, not a reset of the untouched base.
2. Admit all five independent H200 roles against exact source, runtime, checkpoint
   and idle-role evidence. Retain the validator/controller on Arbos.life.
3. Open a fresh MATH epoch covering 6,746 training indices with 750 held out,
   authenticated activation for any currently registered SN120 key, explicit
   submission limits and penalty parameters, and a prospective reward contract.
4. Exercise external bootstrap/upload, independent sampled audits, expanded audits,
   duplicate-zero scoring, penalty-adjusted proposed weights, training, checkpoint
   publication and comparable evaluation. Preserve exact outcomes and actual exits.
5. Authenticate payout inputs, fresh UID ownership, the prospective reward contract
   and single-writer ownership. Old transition/burn timers must stay disabled and
   the old validator guard must stay present. Never pay pilot/test history.
6. Submit the new mechanism's normalized weights and verify chain inclusion or
   finalization. Only then announce that weight setting is live in SN120 Discord.
   Explain agent-based mining, setup, limits, proofs, penalties, and monitoring
   affine.io/llms.txt and GitHub main for versioned updates.
7. Keep repeated epochs running under supervision; monitor real external miners,
   verifier lease failures, upload/manifest integrity, training, checkpoint
   continuity and payout retries. Make source upgrades only at epoch boundaries.
8. Encourage real adversarial participation and test malformed artifacts, fake
   scores/proofs, oversized uploads, deadline writes and replayed reports without
   mixing synthetic contributions into paid scores or training.
9. Independently compare the untouched base and learned checkpoints on fixed
   reserved held-out cohorts, using identical tasks, seeds, graders and budgets.
   Report both regressions and gains. The existing 32-task cohort is diagnostic;
   stable, reproducible held-out improvement remains an unproven completion gate.

The bounded policy rewards unique **fully verified** task indices. It does not
extrapolate correctness to unchecked batches. Its explicit sampled duplicate
coverage limitation must be disclosed before live mining. Infrastructure failures
retry without a fraud penalty. Audits and reward hyperparameters are published
before the epoch; no retroactive policy or deadline changes.

Funding additional infrastructure is authorized if needed. Existing retained
nodes and immutable state are preserved; there is no automatic pod termination.
