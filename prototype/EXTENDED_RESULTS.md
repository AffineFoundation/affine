# CPU/GPU cross-runtime and random spot-check results

The local verifier's original exact-match settings **reject the honest GPU artifact** when evaluated on CPU. Loosening verification requires deliberate calibration: a tested tolerant configuration accepts genuinely altered-weight computations. This experiment therefore supports using the same pinned numerical runtime for the immediate mock pipeline; it does not establish exact weight identity across heterogeneous runtimes.

## Cross-runtime comparison

Both sides use the identical approved SmolLM2-1.7B checkpoint and exact token contexts. Original reference: RTX3090, bfloat16, torch2.12.0, transformers4.57.1. Verifier: local x86_64 CPU, four threads, bfloat16, torch2.14.0, transformers5.14.1. TOPLOC0.1.6 was rebuilt against local torch using private Python3.12 headers; production packages were not changed.

Hardware **and software versions** differ. These results cannot isolate hardware effects, and no second-GPU experiment occurred. The previously retained GPU was externally removed: Lium's ledger reports `user_initiated`, 2026-09-30 17:20:20UTC, total charge$0.382979 for6,266.93billed seconds. This agent did not remove it or rent a replacement.

All12 honest segments fail the original combined zero-fingerprint-error/1e-5log-probability criterion. Worst observed metrics:

| Metric | Honest maximum |
|---|---:|
| Exponent mismatches among128 selected elements | 3 |
| Mean bfloat16 mantissa error | 1.76 |
| Median mantissa error | 1 |
| Absolute full-vocabulary log-probability difference | 0.62977 |

A post-hoc threshold `(exponent≤3, mean≤2, median≤1, logprob difference≤0.65)` accepts this honest trajectory and rejects the four previously tested numeric attacks. It also rejects the additional changed-weight tests. This is one trajectory used to choose its own threshold, so it is not independently validated calibration.

A second post-hoc threshold `(exponent≤8, mean≤2, median≤2, logprob difference≤0.65)` also accepts the honest trajectory and rejects those original four attacks, but **accepts computations with actual first-layer down-projection weights multiplied by1.003 and1.01**. The1.003case changes10,377,162bfloat16 weight values; the1.01case changes all16,777,216values in that layer. The artifacts have regenerated proofs and distributions from the altered model while claiming the approved state manifest. Strict same-runtime verification rejects both. These are concrete counterexamples to treating that tolerant fingerprint configuration as proof of exact weight identity.

Artifacts and full per-segment numbers: `artifacts/extended/cross-runtime.json` and `tolerance-attacks.json`. The latter contains an independently varied threshold grid, post-hoc candidates, and changed-weight artifact hashes. Neither tolerant configuration is installed in the primary verifier.

## Frozen-artifact spot checks

A CPU-honest trajectory is generated by recomputing the approved model on the original output tokens. Its fingerprints and full log-probabilities pass exact local verification. Each attack ZIP is sealed with SHA256 before random challenge selection, reread, and checked again afterward. Real native TOPLOC and probability comparisons determine its failing segment mask. Challenge simulation then samples uniformly without replacement from12global inference segments.

All document structure and all cheap deterministic environment transitions are checked for every submission. Missing proofs, malformed base64, zero proof modulus, and fake observations reject before inference sampling. Selected prefill segments check fingerprints; selected output segments check fingerprints plus all vocabulary probabilities for that output block.

Eleven cases × five audit budgets ×20,000trials produced **1.1million random audit decisions**. All55configurations agree with hypergeometric predictions within five binomial standard errors; largest absolute empirical difference is0.00598. Honest controls have zero rejection. Examples:

| Bad segments | Audit1 | Audit2 | Audit4 | Audit8 | Audit12 |
|---|---:|---:|---:|---:|---:|
| One of12 | 8.33% | 16.67% | 33.33% | 66.67% | 100% |
| Three of12 | 25.00% | 45.45% | 74.55% | 98.18% | 100% |
| Six of12 | 50.00% | 77.27% | 96.97% | 100% | 100% |

Table values are theoretical detection probabilities, supported by the simulations. Location tests cover first prefill, final output segment, scattered segments, and a single changed probability in the final block. Detection is conditional on sampling a genuinely detectable inconsistency. It says nothing about a fraudulent proof that passes the numerical predicate.

The simulation seed is fixed for reproducibility. It does not establish unpredictable production challenges; a deployed sampler must draw fresh validator-controlled randomness after the miner commitment, so miners cannot arrange faults around known challenges.

Reference forward passes were cached before simulated challenge selection. This tests audit-selection detection probabilities, **not reduced inference cost or an optimized production spot-check executor**. Validators still need trustworthy contexts and sufficient prefix computation for each selected segment.

## Reproduce

The trusted GPU-era policy remains separate from miner ZIPs. `trusted-policy-local.json` changes only its trusted local snapshot path after extracting model files from the verified full-state tar; every model and environment file is independently hashed before loading.

```bash
cd /home/const/subnet120-rewrite
.venv/bin/python prototype/extended_checks.py --root prototype/artifacts --threads 4 --trials 20000
.venv/bin/python prototype/tolerance_attacks.py
```

`artifacts/extended/spot-checks.json` records all challenge rates, commitments, corrupted locations, and expected rates. `spot-summary.json` records the agreement check from the completed run. The benchmark is deliberately small; more independent honest trajectories, alternative kernels, repeated numerical trials, and adversarial optimization are needed before selecting deployment tolerances.
