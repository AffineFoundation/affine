Baseline

Each gate round (one per head) scores candidates against the head on a fresh random draw of about 500 tasks from the 19,305-task baseline pool. The draw is not uniform. It follows the Neyman allocation: a task’s chance of being picked grows with the square root of the uncertainty of one head answer on it, roughly √p(1 − p) where p is the head’s pass rate on it (see How the draw works), so tasks the head solves about half the time are picked most often and tasks it always or never solves are picked least (a small uniform floor keeps every task in play). As the head improves, more tasks move toward a pass rate of 1 and the draw shifts toward the tasks it still finds hard.

How the draw works

priors/baseline_v1.py

When a round opens, the gate takes a read-only snapshot of the prior table, where si / ni is the head’s record on task i (solved / sampled), and sets each task’s inclusion probability:

πi = N[(1 − floor) · aiΣj aj + floor · wiΣj wj]
ai = wi · √vi,  vi = E[p(1 − p)],  p ~ Beta(si + 1,  ni − si + 1) = AB(A + B) (A + B + 1),  A = si + 1,  B = ni − si + 1

wi is the task’s share weight (size shares: each environment counts by its size, so every task has the same wi). Probabilities are capped at cap and any excess is spread over the uncapped tasks. Each task is then included independently with probability πi, using a commit-reveal seed fixed by a future block hash:

task i is drawn  ⇔  ui < πi,  ui = sha256(version | draw | seed | task) / 264

The knobs, with the live values:

  • floor = 0.10 — the uniform share of the draw. A higher floor flattens the curve; at 1 the draw would be uniform.
  • √ — the Neyman choice: drawing in proportion to the standard deviation, not the variance, minimizes the variance of the estimate for a given sample size. That is why the peak is gentle (about twice the tails) rather than as sharp as p(1 − p).
  • ni — the samples per task in the prior (halved when the head changes, so old evidence counts less). A task the head always or never solves still has vi ≈ 1/(ni + 3), so with few samples the tails stay near 2%; as the prior collects samples the tails fall and the peak sharpens.
  • N = 500 — the expected draw size. It scales the whole curve (Σ πi = N).
  • cap = 0.10 — the most any task can get. Not binding today: the highest probability is under 4%.
  • n_init = 2 — the pseudo-count for a task with no samples yet: it starts at its environment’s average pass rate, worth n_init samples.

The gain is a Hájek (inverse-probability ratio) estimate per environment, so the non-uniform draw does not bias it. Every drawn task i is weighted by 1 / πi, with di = candidate minus head pass rate:

me = Σi∈e di / πiΣi∈e 1 / πi,  Δ = Σe sharee me

x: percentile of tasks sorted by the head’s current pass rate (0 = hardest, 100 = easiest). Both charts use the same order. Curves are averages over equal-count bins of about 120 tasks, rounded; task ids and per-task values stay private. Computed from the live prior table with the gate’s own draw code (what the next round would use; an open round keeps the snapshot it took when it opened), refreshed every 15 minutes.
