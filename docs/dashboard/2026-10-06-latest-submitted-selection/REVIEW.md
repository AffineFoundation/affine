# Deployed latest submitted-count selection

The existing rich dashboard selected E13 by default because `defaultRecord('batch', rows)` preferred the newest record with `finalized=true`. That flag came from the legacy scores file. Later E14–E18 had genuine completed unaudited training and available submitted counts, while their independent audits continued asynchronously. They were marked `phase=trained`, `finalized=false`. The default therefore showed E13's10 rather than E18's311.

The archived patch changes only the deployed `website/network.js`: select the latest available submitted-count row; distinguish submitted, unaudited learner-eligible and fully audited/accepted counts; show an unavailable independent audit breakdown truthfully. It preserves the existing rich layout, miner grid, evaluation and incentive graphs. It does not replace the asset with the separate newer frontend in this repository. No HTML, CSS, server, DNS, model, controller, optimizer or authority state was changed.

E18's actual public count at deployment was311 submitted pairs from131 identities,276 learner-eligible unaudited pairs and35 duplicate-task exclusions. Its original signed learner population/metrics separately establish256 selected training inputs,20 eligible inputs not selected under the256 cap and one actual optimizer update8→9. The current exported row does not contain the256 selected field, so the JavaScript does not invent it. Submitted pairs do not imply verified acceptance.

`network.js.patch` is the exact minimal deployed diff against the private timestamped backup. `selection-controls.cjs` is the exact ten-control script used before publication; it intentionally preserves the original operational file paths and historical E18 assertions for provenance.
