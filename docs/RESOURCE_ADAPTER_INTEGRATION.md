# Resource adapter integration

The active bridge now dispatches `resource_prime_v1` and the distinctly versioned
`resource_prime_v1_controlled`. Contracts use `environment-execution-contract-v2`.
The controlled mode declares `dependency_scope: provider-namespace-controlled`
and `dependency_closure_reviewed: false`; it verifies the packaged provider
namespace but does not establish complete native/platform dependency closure.
Strict full-closure mode requires approved native pins and a native verifier and
fails closed when those are absent. The worker isolates its protocol descriptor
from native stdout and enforces response deadlines.

The following earlier design notes describe additional integration requirements;
references to v1 contract schemas or future dispatch are historical.

The next adapter version can use `subnet/adapter_resources.py` to bind environment execution resources. It is isolated from the active adapter and has not changed current epoch source pins.

The concrete bridge is `subnet/resource_session.py`. Use an outer `EnvironmentSpec` with adapter `resource_prime_v1`; its config contains only `signed_resource_spec` and the trusted operator public `authority`. The signed payload is `resource-environment-spec-v1`: original base environment plus `execution_resources`, the bridge/helper source-byte hash and resulting resource source hash. Outer id/budgets mirror the base environment, version matches the execution contract, and source_hash matches the signed payload. The worker authenticates its Ed25519 signature before descriptor/archive access. The contract is `environment-execution-contract-v1`; `build_contract` requires reviewed dependency closure, exact dependency descriptor ID/archive SHA/object key, task bundle audience references and optional immutable Docker image ID/repository digest. Provider footprints include source and packaged resource bytes such as import-time prompt templates. No URLs or credentials belong in the resource contract.

The precise active-module changes at the coordinated boundary are: allow `resource_prime_v1` in `EnvironmentSpec.from_dict` and validate with `resource_session.validate_outer_spec(result.to_dict())`; dispatch that adapter in `create_session` to `resource_session.create_resource_session(spec)` before constructing the existing EnvironmentSession. The proxy implements reset/step/close, so model/harness code need no environment-specific edits. Its version/canonical hash match the outer Runtime bindings. Role-local descriptor/archive/cache/audience paths come from `AFFINE_RESOURCE_BINDINGS_FILE` outside the public spec. The signed source bundle must contain the exact bridge/helper bytes and base environment sources, plus only miner-authorized resources.

Before importing providers, fetch the signed descriptors and only role-authorized archives. Call `prepare_environment(contract, descriptors, archives, cache, audience='miner'|'verifier')`. The caller owns authenticated R2 transfer; missing private grader bytes are acceptable for a miner and fail for a verifier. Materialization enforces archive identity, exact members and file hashes. Cache reuse rechecks byte membership. The proxy starts a fresh Python `-I -B` worker, excluding hostile PYTHONPATH/sitecustomize, with the authenticated `dependency_root` before site-packages. `verify_provider_before_import` requires disabled bytecode writes, rejects existing unlisted executable caches/artifacts and preloaded provider modules, checks actual import resolution, and verifies package versions/namespace bytes. `-B` alone can still read forged cached bytecode. Signing/bootstrap dependencies belong to a separately approved interpreter platform; do not silently treat previously loaded bootstrap libraries as freshly guarded provider code.

At task reset, call `prepare_task` before constructing mapped upstream TaskData. It calculates the versioned task hash using symbolic `resource://<descriptor-id>/<relative-path>` fields before replacing host paths with local resource roots. Both hosts therefore return the same canonical identity. Preserve this ID in reset/rollout/replay instead of recomputing upstream Task.hash after path mapping. Ordinary tasks without file resources receive the same versioned canonical data/config envelope. A miner receives the canonical ID but cannot bind a verifier-only grader directory; its sandbox setup must use separately approved miner-setup bytes. The private verifier reconstructs the full original task from the private bundle. This separation needs a miner setup factory hook in the adapter, rather than calling the private upstream grader constructor in both roles.

Immediately before starting each container call `verify_docker_before_start(contract)`, and pass its returned immutable image ID to docker run. It inspects the actual Docker ID and, when supplied, repository digest. Pull by the signed repository digest if absent, then verify again; a mutable tag does not authorize a different image. Build-context tasks require the original signed build context and an operator-approved resulting image ID. The contract does not claim remote hardware attestation or safe execution of arbitrary task-authored host code.

Required coordinator/core hooks are: transport resource descriptors and audience-specific archives in the epoch source bundle; launch a fresh authenticated provider worker; include the contract and resource adapter code in the new version source hash; persist canonical task IDs; use the contract's immutable Docker image instead of task-provided mutable tags; keep private grader bundles out of public/miner downloads; and retain old source/resource families for existing artifacts. `Runtime.verify` must reconstruct the same version/contract and canonical task identity. Native dependency wheels/extension libraries still need an explicitly approved platform footprint; this Python-only transport must not claim that missing native closure is enforced.

Ten resource tests pass. The new actual worker/proxy control grades a genuine original Verbatim sample at1.0 after loading an authenticated materialized verifiers namespace, rejects altered signed payloads, forged cached .pyc and a replaced cache namespace symlink, and excludes hostile PYTHONPATH/sitecustomize. The other nine tests cover image IDs/digests, private grader separation, portable task identity, source/shadow changes and archive tampering. These are real worker controls, while production signed-resource epochs still await the coordinated integration boundary and reviewed dependency/platform closure. A source requiring private grader files cannot run as a miner through this generic factory yet: the bridge rejects it explicitly until its separate trusted miner-setup factory is implemented.
