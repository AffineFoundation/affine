The prospective `bounded-parallel-checkpoint-GET-v1` option is absent by default. A new approved execution source and ROOT-signed manifest must opt in with `checkpoint_download_policy`, exact approved file sizes, 2–4 workers, and a disk floor of at least 2 GiB. It changes checkpoint transport only; model bytes, native grader, sampler, and tensor numerics remain unchanged. Existing requests and source contracts are not amended.

The operator must obtain sizes from a genuinely authenticated full-readback publication inventory. No HEAD-only or directory-name inference substitutes for that evidence. An approved manifest example has fields `version`, `workers`, `file_sizes` (same names as checkpoint.files), and `disk_floor_bytes`. Each member is at most 5 GiB and total at most 20 GiB. Admission reserves missing bytes plus the largest concurrent temporary members and the disk floor; deployments must reconcile this stronger reserve with their existing capacity gate.

Each member uses its own HTTP session, authenticates its complete SHA and exact size, and replaces its partial path atomically. A same-checkpoint process lock prevents duplicate candidate hydration; the existing outer owned-checkpoint lease still prevents retirement of live input. Catalog member writes run serially. After a sibling failure, completed authenticated members remain cataloged for normal software retirement/reuse; partials are removed by the original downloader. Unowned existing members, symlinks, hardlinks, altered files and preexisting partials are refused. Reports, logs and immutable proofs are preserved. External mapped caches retain the original full-hash path.
