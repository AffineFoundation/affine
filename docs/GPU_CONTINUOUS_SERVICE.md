# Sustained nonpayable GPU epochs

`subnet.gpu_service` and `subnet.remote_backend` run the complete synchronous experiment through the existing Controller/Gateway protocol with remote GPU jobs. The owned unit is `affine-gpu-continuous.service`, with operator configuration `state/gpu-continuous-config.json` and immutable epoch/audit/training history under `state/gpu-continuous`. This service never calls a chain weight writer or loads a validator wallet. Each opening performs a current read-only SN120 registration lookup and admits only the operator's dedicated, already registered UID131 Ed25519 identity.

The controller publishes an immutable approved checkpoint and a signed challenge with encrypted per-miner upload capability. The retained worker receives a signed operator delegation for that owned identity and one presigned R2 PUT. It downloads the approved model/tokenizer objects directly from R2, checks their exact hashes, generates K1/L1 batches using the challenge's native environment and harness, then uploads its cumulative ZIP. The signed start/deadline window is enforced during search and before upload. Writes close at the published boundary: the Gateway freezes a single atomic object snapshot, rejects completed-after-deadline bytes, and publishes the immutable final artifact for independent inspection. There is no early-freeze shortcut in the continuous service.

A fresh remote verifier loads the independently approved weights, checks every probability array/TOPLOC fingerprint and replays every environment turn. The operator binds the report to the exact frozen artifact, signs the audit, computes duplicate-zero unique-environment points, and publishes scores. The ledger maps those points to the current registered hotkey. Proposed weights are recorded locally and publicly signed epoch scores remain permanently nonpayable; the existing payout selector excludes this history.

Before and after each training epoch, the worker runs fixed original heldout indices2/3 under a free autoregressive128-token policy. These are disjoint from *all* configured training indices, including inactive environment groups. Each successful row includes the actual replayed task hash and exact index/seed; failed executions are separate failures, never completed zero rewards. Dataset identity binds the environment spec, harness/source, backend profile, effective runtime source hashes and installed package versions. Records use the worker's completion timestamp and go to `state/evaluations/nonpayable-gpu-continuous-*.json` for the public dashboard.

The trainer independently re-audits frozen ZIPs and selects only fully audited positive/negative pairs. The sustained training policy is `bf16-full-adamw-checkpointed-v1`: dropout-free full-parameter optimization, nonreentrant gradient checkpointing, no KV cache, BF16 parameters/gradients/moments, AdamW at1e-5 with `foreach=False`, and the reference-relative sequence-preference objective. CPU/GPU or cross-hardware tolerances remain unchanged. The earlier measured1.7B control required14.16GB peak allocated on the retained RTX3090 and changed192/218 tensors; this establishes feasibility, not a promise of quality improvement. Curated public candidate mining and unconstrained heldout evaluation are labeled separately.

New checkpoint bytes stay on the retained host. The operator delegates exactly six object PUTs, then independently streams and SHA256-checks every R2 model/tokenizer file before signing its immutable authority-specific descriptor. Only after after-training evaluation and publication does the next epoch open on those new weights. Remote disk reserve requires at least two checkpoint sizes plus2GiB; existing history is preserved. No full checkpoint is copied onto the operator's nearly full disk.

The initial configuration rotates six genuine source families: Verbatim, mathematical tasks, When2Call native tools, IFEval, Oolong original date task215 and RGym count_bits. At most three environment batches are accepted per ZIP, retaining the100MB transport cap. This is an initial feasible rotation; other original environments/resources remain separate coverage work. The complete approved source bundle includes static gzip/shell/gitignore data needed by the source hash, while excluding credentials and bytecode. Resource-contract enforcement remains explicitly reported by each worker; this rotation uses the original native adapters, rather than claiming the separately controlled resource pilot has passed.

`subnet.remote_runner` persists each worker's PID and `/proc` start time independently of the SSH session. Recovery first checks the same job's complete report and authoritative process status. An active job is polled, a status transport failure does not create a replacement, and only verified terminal failure or absence of any exact job process allows a new attempt. Reports bind job ID, signature digest, checkpoint, epoch, source/package pins and numerical/backend policy. A deliberate stop is recognized by the unit's success exit policy, and the retained rental stays up.

Actual epoch completion, quality and failure counts come from state records and the public dashboard. Enabling the service is not evidence that an epoch has finished or that heldout performance improved.
