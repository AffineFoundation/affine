# Prospective decoupled learner and continuous audits

This implementation is opt-in. It does not reinterpret historical strict sampling contracts or activate a production profile. GPU qualification and operator admission are required before a signed epoch may use `forced-inverse-cdf-prefill-v2`.

A miner uses the pinned weights, tokenizer, harness and public forced uniform draws to generate tokens with a KV cache. The verifier performs one teacher-forced target-model forward pass per turn, checks full token probability evidence and native TOPLOC fingerprints, replays the environment, and checks every token against its forced draw's inverse-CDF interval. Tokens excluded by nucleus sampling are invalid even if a tolerance would cross their boundary. A token outside its interval but within the signed calibrated CDF bound is ambiguous, not verified and not fraud. A token farther outside is invalid. The distinct `forced-inverse-cdf-prefill-support-v3` contract additionally signs `support_adjudication: exact-cached-replay-v1`: if the reference nucleus excludes a submitted token, the verifier replays the original cached sampler under the committed draws before classifying it. A genuine numerical support crossing passes only when every cached reference token matches; an invented excluded token is invalid. Older v1/v2 contracts retain their rules. Calibration is bound to the exact checkpoint, runtime, backend profile and normalized harness; successor checkpoints require fresh executed controls. Hard maximum tolerances cannot be increased by a reported measurement.

`continuous_audit_service` reads immutable signed populations independently of the learner. It chooses committed children without replacement using randomness produced after commitment, captures only selected proof objects, checks original upload time and size, conditionally copies the original ETag, and reads and hashes all copied bytes before creating a read capability. The learner's token-only transport does not pretend every declared proof has already been captured. Storage failures retry the same selected record; a missing or corrupt committed artifact is separately authenticated invalid-storage evidence and is not a fabricated GPU verification result.

A verifier assertion alone does not earn an audited result. Score admission authenticates the original operator-signed queue request, original worker-signed terminal request, immutable committed child, executed source hashes, runtime versions, backend profile and numerical policy. Repeated evidence counts once. Ambiguous results may be resolved only through explicit signed reference adjudication. Infrastructure or unresolved numerical uncertainty does not count as validity or fraud.

Each epoch's score is unique eligible task count multiplied by a recent-cohort validity estimate and the signed penalty policy. The estimate uses both recent history and the current epoch/checkpoint cohort, preventing old reputation from eliminating current checks. Confirmed-invalid evidence can reduce probability and apply reward multipliers or a temporary blacklist. These are reward penalties, not wallet withdrawals. Unaudited training inputs are explicitly labelled unaudited; the trainer neither waits for nor repeats this audit.

At each UTC hour cutoff H, completed epochs in `H-3600 < completed_at <= H` receive immutable snapshots using evidence available by H. Raw penalty-adjusted points are summed across all these epochs and normalized once into `continuous-hourly-weights-v1`. Earlier epochs remain available for audits and recent-history evidence but do not repeatedly earn old points. Snapshot references bind their epoch, round, checkpoint and population hash. The artifact proposes weights; this module does not transact on chain. The historical strict reward writer must not consume this new contract implicitly.

The service joins the existing authenticated verifier SQLite queue and does not create another listener. It bounds outstanding jobs and selections per tick, persists selections before proof access, and recovers an already-written original signed job without changing its selection, source or URLs. A terminal expired job without authenticated scientific evidence remains unknown; automatic capability renewal and a separately authenticated reference execution still require explicit integration.
