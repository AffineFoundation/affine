# Small commitment history and original completion

History retains the legacy whole-ZIP `frozen[miner] = {url, sha256, size}` layout for legacy manifests. An epoch explicitly signed with `small-commitment-pairs-v1` instead publishes `transport_policy`, a `commitment` containing its renewable frozen URL, original raw-byte SHA256 and size, and ordered `artifacts` containing each signed slot/environment/index/batch digest/payload digest/size and frozen URL. Child hashes are labelled `declared-payload-hash-until-selected-verifier`. The separate authenticated audit route records actual selected verifier work; route publication does not assert child verification.

Publication performs a bounded GET of each original frozen commitment, checks raw bytes and miner signature, and verifies original epoch/checkpoint/source and complete ordered child inventory. It never opens the child ZIPs. Noncanonical original JSON framing is preserved by hashing the fetched original bytes rather than reconstructing canonical envelope bytes. Staging keys and old presigned URLs are not reused. Original receipts, manifests and ledger records are not rewritten.

## Operator-only completion of the original E11

The original E11 controller stopped in `after` when legacy history indexed `frozen_key` on a small-commitment receipt. The original compute source and results remain authoritative. A root-reviewed completion amendment may stage a separate CPU operator snapshot containing **only** this `subnet/publication.py` change over the exact original sealed operator snapshot. Record and root-sign original source, original and amended module hashes, epoch, state/config paths and input-file digests as a publication-only amendment; do not replace the GPU source bundle or signed epoch manifest.

Immediately before a single resumed `--once`, require the original stopped process absent, the same active epoch still in `after`, all original manifest/scores/verified/empty-closure files unchanged, no accepted batches or training job, unchanged checkpoint CP6a and committed optimizer step3, and the original completed evaluator job/report binding. Use the unchanged original config and state. The existing `after` path reuses the completed evaluator request, publishes history, validates the committed trainer journal and reward closure, then completes the original epoch. Do not rerun mining/audits/training, change deadlines, relabel GPU source, advance optimizer state, or reset the epoch. Save original process identity and actual resumed terminal receipt. Root alone signs and launches.

## Other consumers reviewed

`RemoteController.finalize` handles explicit commitments, selected child verifier submissions and cached original reports. `compact_training_inputs.prepare_submissions` expands actual accepted `artifact_audits` to their frozen child receipts; nested original receipt validation binds that child. Whole-ZIP branches in training and the synchronous local controller are legacy paths, not the admitted remote compact pipeline. Scoring uses accepted batches and authenticated outcomes; reward publication uses original signed scores and durable checkpoint/state evidence, including an explicit no-update closure. Neither indexes a parent frozen ZIP. The dashboard reads epoch results rather than these history child routes; its existing work is unchanged.

Legacy replay builders, whole-ZIP retention scripts and older `check_*_evidence.py` helpers still require whole-ZIP receipts. They are not the active E11 completion path and must not be used to claim full child verification for a commitment epoch. A future adaptation must explicitly enumerate original child receipts and preserve their assurance and actual audit lineage; this publication fix does not silently convert a commitment digest into a ZIP digest.
