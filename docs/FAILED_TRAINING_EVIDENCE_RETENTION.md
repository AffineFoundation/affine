Failed export evidence retention is an operator policy, default off. It does not change any training, optimizer, sampler, verifier, or publication code, and is not part of the immutable fc401 recovery source.

`ops.failed_training_evidence_retention.retire` accepts the explicit policy `{'version':'failed-evidence-after-durable-recovery-retention-v1'}` and a ROOT-signed exact file grant. It requires the genuine ROOT durability ACK, original replacement job/report/state descriptor, actual terminal handles, and explicit post-update recovery declaration binding the same failed original. A report or partially uploaded optimizer candidate cannot authorize disposal.

The grant may cover the failed `state-000000.safetensors` and bounded original `evidence-*.json`/`failure-*.json` sidecars in the original job's exact transfer directory. It protects every unlisted member, all model/cache state, original job/log/failure records, and source files. Each file must match its original full SHA, ownership, single-link inode and content-change timestamps; inherited optimizer leases, GPU use, open descriptors, mappings or a live workspace job defer disposal.

The private archive key is fixed to `private/failed-training-evidence/<original-job>/<name>`. `bucket_archive` performs an immutable streaming PUT and a complete streaming GET, with a bounded memory buffer. An already existing object is fully checked instead of replaced. No local unlink occurs before full readback verifies the same original bytes. An atomic exclusive grant journal and per-file archive receipts support replay after interrupted archival or deletion. Failed evidence remains forensic data; it is never promoted as optimizer state.

`schedule_after_durability` is a default-off asynchronous completion hook. It accepts only explicit ROOT-signed original failure blueprints, uses the real durability ACK, and asks the trusted controller to sign the bounded per-invocation operator grant. The remote dispatch adapter must pin this module and the original workspace. This hook is prepared code, not an active installation. Its dispatch exceptions are deferred and do not block learning. A concrete pinned remote adapter and service integration require separate review; no automatic-cleanup claim is made for the current deployed source.

The tests use isolated signed fixtures and toy CPU state descriptors. They cover disabled behavior, genuine lineage, wrong source, forged/uncommitted ACK, report changes, partial/HEAD readback, ownership and unlisted files, active leases/jobs, private streaming archival, crash-after-unlink replay, and the asynchronous hook. They do not claim a production checkpoint14 or archive of the actual failed shard zero.
