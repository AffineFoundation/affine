# Controlled original Calendar common pipeline

The retained GPU runs a nonpayable common pipeline under `affine-native-eog-common.service`. It uses pinned Qwen2.5-0.5B-Instruct weights, the qualified 32K selective-output-head numerical profile, original Calendar tools and grading, and seven agent turns including the terminal reply. No chain weights are submitted.

The initial original training task is Calendar row 54. Rows 0 and 3 are fixed, disjoint heldouts with free autoregressive output; they are not the curated training policy. Training proposes public tool calls and varies only the first relocation destination between two equally long public locations. This is curated target-model computation, not a claim of autonomous problem solving or general environment coverage.

The immutable portable-v4 source uses seed-content commitments for private fixture/database identity. Relocating identical seed bytes preserves the public descriptor and six exact native tool observations. The destination Docker image is qualified by raw configuration digest, ordered layer hashes, architecture and OS. Private original seeds and grader queries stay in a separate operator directory; the public manifest contains descriptors and commitments. The actor exposes tools and a sealed scalar terminal outcome. This is a controlled cohost deployment; external hostile miner isolation is not established.

The public checkout preserves the earlier terminal source. To reproduce the
qualified portable variant, first create a new independent source copy, then
run the preparation utility from the original checkout:

```sh
mkdir -m 700 /tmp/affine-eog-portable
git archive HEAD | tar -x -C /tmp/affine-eog-portable
.venv/bin/python -m ops.prepare_native_eog_portable_source \
  --source-root /tmp/affine-eog-portable
```

The utility changes exactly two reviewed modules, verifies their baseline and
qualified output hashes, rejects the original checkout and hard-linked files,
and records the transformation. It does not materialize fixtures, load weights,
start services or qualify a deployment. Never use a running or frozen job tree
as its destination. Private fixture preparation and source/job signing remain
separate operator steps; `ops.materialize_native_eog_common` deliberately
requires this portable source version.

Transfers use signed direct R2 reads and cumulative private PUTs. The signed artifact policy permits 250 MB compressed and 500 MB uncompressed, retaining full float32 output-vocabulary probabilities. Deadline freeze snapshots atomic R2 response bytes and metadata; late writes cannot replace the frozen artifact. Full inference and fresh native replay audits precede training. A qualifying batch produces proposed scores, a real full sequential agent-only preference update, a new immutable checkpoint, and comparable heldout records. Passing standalone controls or uploading a batch does not establish that a completed epoch trained.

Operator state is `state/native-eog-common`; configuration is `state/native-eog-common-config.json`. The running source is a separately pinned source archive, not the mutable checkout. Initial inference requires 12 GiB free VRAM and training requires 20 GiB before loading; jobs wait without restarting other roles. The full seven-turn optimizer was measured below its 8 GiB allocation cap. The retained machine remains running.

Use `systemctl --user status affine-native-eog-common.service` to inspect the controller and `systemctl --user stop affine-native-eog-common.service` for maintenance. Preserve role liveness markers, frozen receipts, and checkpoint history when resuming. This service is permanently nonpayable and must not be connected to the live weight writer by treating its scores as production rewards.
