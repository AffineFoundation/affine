# Prospective scientific learner admission

This default-off code admits a new scientific source, not an ordinary CPU
orchestration restart. Nothing is signed, staged, rented or activated by this
module. Old `durable-pinned-learner-service-v1` policies retain their ordinary
source/qualification versions and exact 177-file runtime closure.

The new runner policy is `durable-pinned-k2l2-learner-service-v2`. It retains all
old policy fields and adds `scientific_admission_file_sha256` to pin the helper
before import. The approved source is a NEW
`k2l2-miner-bound-scientific-source-approval-v1`, and qualification is a NEW
`k2l2-miner-bound-training-qualification-approval-v1`. Neither can be relabeled
from an old approval. Each original evidence descriptor uses the existing
`verify_admission`: exact private file hash, explicit signature encoding, actual
ROOT Ed25519 signature, exact canonical payload hash.

The source approval retains `approved`, `source_sha256`, `optimizer_reset:false`,
`historical_relabel:false`, full/runtime file maps and original evidence paths.
It adds the authentic `predecessor_source_approval` and
`predecessor_learner_policy` descriptors, sorted `runtime_execution_files`, exact
`runtime_changes` (`path:{before:old_sha_or_null,after:new_sha}`), and
`contract_sha256`. Derive the runtime map from the actual merged source's
scientific execution lists; do not guess a count. The predecessor map has 177
files. The new map preserves every old path and adds exactly
`subnet/sampling_uniqueness.py` and `subnet/trajectory_identity.py`. Every runtime
hash must be in the new full source map, and the declared delta must exactly
match it. Full filesystem membership/hashes remain checked by the runner.

The new contract digest includes K=2, L=2, commitment_max_batches=3, the complete
`sampling_policy` (v5, max_attempts=1000, unchanged calibrated support with
exact-cached-replay-v1), selected-token-logprobs-v1, no token-only policy,
small-commitment-pairs-v2 and committed-unaudited-training-v1. This is not a
numerical-tolerance or training-objective change. Authentic predecessor config
bytes bind preserved parameter inventory and optimizer genesis. All existing
runner guards for physical host, original state directory, committed optimizer,
reward activation, source/translation hashes, singleton and predecessor-unit
exclusion continue to apply.

## Actual disposable GPU qualification, before ROOT approval

Use a disposable SM90 H100/H200 qualification namespace with the exact merged source,
source bundle, runtime inventory and unchanged scientific numerical profile.
Pin the authentic current parent checkpoint and original Adam descriptor/shards;
never reset or mutate the live parent. ROOT must review original process terminal
and full reports before signing the new attestations. Do not infer success from
a lock, a pending intent or a lost polling handle.

1. Generate four genuine distinct rollouts with four distinct nonces: two native
   successes and two native failures on one task. Verify the entire batch.
2. Reject repacked copies, repeated attempts, wrong miner context, out-of-range
   nonces and token mutations. Compare legacy draw bytes with the old source.
3. Native grading must admit all four outcomes atomically. Confirm two disjoint
   pairs per task without Cartesian expansion; each task's total weight stays
   unchanged. Train a disposable update from the fully authenticated original
   model/FP32 Adam parent. Confirm finite loss/full parameter gradient coverage
   and the expected global-step advance. Preserve the original global step,
   parameters, hyperparameters and optimizer genesis on the live node.
4. Keep the actual training function and its local isolated BF16 checkpoint
   output intact. Report that local model export truthfully; do not upload/promote
   it or export Adam state from this disposable qualification. Archive the original qualification reports and terminal, and
   independently GET/hash every metadata object. The ROOT approval attests actual
   original wait0 and complete metadata readback. It does not claim new checkpoint
   or optimizer publication; that is proven by the subsequent real v5 epoch.

The qualification approval retains candidate source and translation path/hash,
and adds `original_gpu_report` and `durable_readback_ack` descriptors. The ROOT
report version is `k2l2-miner-bound-sm90-qualification-result-v1`; exact fields and
required control names are in `ops/k2l2_scientific_admission.py`. The separate
ROOT ACK version is `ROOT-k2l2-scientific-qualification-metadata-readback-ACK-v1`.
It binds the canonical report, signed original scope payload, original raw result
file, terminal hash, candidate source and actual
full independent metadata readback. The report declares actual GPU hardware,
SM90 profile and disposable-local-model-no-state-promotion qualification class.
It records local model export, no model upload/promotion, and no Adam export. An H100 qualification
is not an observation of H200 execution: separately admit and check actual H200
role nodes against the new source/runtime before production activation. These signed attestations record ROOT review; the CPU
helper does not itself recreate GPU experiments or certify learning gains.

## Prospective handoff

Drain the existing original epoch/job naturally. Preserve its checkpoint,
optimizer, opening and receipts. Build a fresh new CPU/runtime namespace and
explicit new native eligibility authorization/boundary for K2/L2 (the old K1/L1
boundary cannot be reused). The running private runner can differ from GitHub
main: port only these reviewed admission branches into a new frozen copy and
pin all operator helper bytes. Reconcile any CPU-peer grant against its actual
new source inventory rather than retaining a source177-only grant. Exclude the
old unit without deleting evidence. Validate a full new policy in check-only
mode; then ROOT alone authorizes activation at a new opening. No approvals or
production launch are included in this patch. Never replay or rewrite old jobs.
