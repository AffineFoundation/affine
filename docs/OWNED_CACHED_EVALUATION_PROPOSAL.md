# Prospective owned cached evaluation

The running fixed-32 evaluator and its existing reports remain authoritative for their own pinned cohorts. This opt-in experiment adds `owned-cached-native-evaluation-v1`: the operator-owned evaluator generates with the normal cached autoregressive harness and directly invokes the qualified environment grader. It does not build TOPLOC proofs or run a second probability prefill. The signed job pins both the owned evaluator and cached sampler implementation. Results explicitly say `verified:false`, `native_graded:true`, and `proof_verification_performed:false`; they are diagnostic evaluation results, not miner audit evidence or reward eligibility.

A comparison must run both checkpoint05de and checkpoint76bc under this new harness with exactly the same environment/native grader, fixed indices and seeds, normalized harness, model runtime and source pins. The cohort fingerprint excludes checkpoint identity but includes those other inputs. A prior uncached result cannot be silently compared as if it used the new cohort. Actual runs must retain ROOT-authenticated requests, independently authenticated original worker reports, original process terminal evidence and full checkpoint hashes. No throughput or quality result is available yet.

Per-task telemetry records actual cached model forward count, input-token count, cache reuse, generation wall time, token selection wall time, native reset/grading time, prompt rendering and decoding. Probability-prefill, TOPLOC generation and TOPLOC replay counters are explicitly zero. Grader failures are infra failures rather than wrong answers. CPU controls exercise real tiny-model cached generation and mocked environment transitions; they do not qualify a production MATH grader or a 7B H200 throughput claim.

Before a future mining window opens, a prospective operator prewarm stage can hydrate the committed checkpoint onto the configured physical miner, check every declared file's size and SHA, and persist the actual role/cache ownership entry. It must follow durable checkpoint publication and successful exact-checkpoint sampler calibration. Start the signed mining window only after that stage completes. A partial download or capacity problem postpones opening; it must not consume the already-issued window, invent an earlier cache completion, alter sampler seeds, or move a still-running miner job. Role swaps require the physical checkpoint ownership ledger permutation reviewed separately for E15.

Deployment remains pending an exact source bundle, signed opt-in evaluate job, actual two-checkpoint qualification on an idle approved machine and ROOT review. Existing evaluation, mining and verifier services have not been changed.
