Verifier download headroom is a default-off operator policy, outside every immutable scientific source. The existing two-GiB post-completion disk floor alone does not reserve a next job's downloads.

The new worker option is `--owned-capacity-policy /absolute/ROOT-signed-policy.json`. The signed policy declares version `owned-verifier-download-capacity-v1`, `checkpoint_inventory_directory`, `disk_floor_bytes` (at least 2 GiB), `extra_temporary_bytes`, `max_submissions`, and `poll_seconds` (1–60). An immutable ROOT-signed `<checkpoint-id>.json` in that directory binds each exact model member's SHA and actual full-readback size to the checkpoint descriptor payload SHA. A signed inline `checkpoint_inventories` map is also supported for isolated bootstrap/control use; production should use automatic per-checkpoint records.

Before launching any backend, the worker holds the incoming checkpoint leases and computes missing model bytes, all input byte caps, one largest temporary/replaced object, additional scratch allowance, and the disk floor. An unchanged authenticated owned receipt can credit existing bytes using full inode metadata; no extra weight hash is added. The original backend still hashes every approved member before model load. Changed or unregistered members, interrupted `.partial` files, external caches and unowned content receive no optimistic credit. Existing partial bytes already consume observed free space. Retry jobs can credit the shared owned cache under its inherited lease on the same filesystem.

If capacity is insufficient, only obsolete catalogued owned checkpoints are eligible for eviction, with existing inode and lease guards. The incoming checkpoint remains protected. The parent records capacity observations and renews the SAME original claim while waiting at bounded intervals. It sends no `fail` or invalid-proof report and starts no backend. Original job/lease expiry ends the wait as infrastructure deferral; it does not grant a replacement job or rewrite history. No claim/report/SQLite semantics are changed.

The separately pinned `capacity_bounded_verifier_backend.py` authenticates the original job/manifest and full runtime inventory before scientific imports. It wraps only model/input GET byte ceilings for exact approved URL/SHA/destination triples. Model limits become their authenticated full-readback sizes. Child artifact limits become their exact captured commitment size only after the original frozen-submission validator authenticates the miner commitment, captured object, source/checkpoint and URL. Legacy inputs retain the original signed manifest cap. A different path/digest under an approved URL refuses; unrelated transport is unchanged. Original SHA/model/parser/proof/sampler/native-grader logic remains unchanged. This tighter transport bound is required for honest reservation: the old reader permits up to 20 GB per model member and LONG permits 2 GB per artifact.

`verifier_capacity_publication.enqueue` consumes the genuine original `commit_remote_checkpoint` full-readback `staged.objects` receipt and signs one immutable descriptive model-size record. Its default-off CPU launcher hook preserves the original return value and publication behavior. These records authorize no job, optimizer promotion, proof or model. The independent metadata observer backfills the currently committed authoritative checkpoint FIRST and any genuinely published checkpoint needed by authenticated queued/leased original verifier jobs from its controller-owned completed publication journal; subsequent genuine authority checkpoints are selected automatically, persists the signed outbox, and retries seven exact ROOT-approved SSH metadata routes. Each remote installer verifies the ROOT signature and full metadata bytes before an exclusive atomic file publication. No model download or GPU operation is involved. Eight remote calls maximum per observer tick, each timeout 30 seconds, and rotating pending work prevent offline older records from starving a new checkpoint. Existing grants and per-replica receipts remain immutable across shutdown/restart.

The metadata observer command, under ROOT scope, is `python -B -m ops.verifier_capacity_publication --policy POLICY --authority ROOT_ID --seed-file EXISTING_SEED --publication-state PUBLICATION_STATE --controller-state CONTROLLER_JSON --queue ORIGINAL_QUEUE`.
