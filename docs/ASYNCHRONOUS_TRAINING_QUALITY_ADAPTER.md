# Asynchronous quality adapter proposal

Operator-only; no deployment, inference, signing, audit replay or training barrier. `training_input` authenticates the original job/manifest and calls the existing `RemoteJobs.checked`, then requires the original ROOT-signed durable publication to match that exact job, namespace, full descriptor, checkpoint and optimizer lineage. It maps the original finite loss/gradient/margin diagnostics and honest BF16 export change flag. A staged or missing publication is pending, never a completed update.

`evaluation_input` likewise uses original checked evaluator jobs plus existing ROOT-signed evaluation exports. Counts, exact indices/seeds/task hashes, native verified outcomes, source/runtime-derived dataset identity and checkpoint must match original reports. Original evaluations remain untouched. `comparison_views` labels only a derived comparison; it preserves original execution epoch/phase/time in provenance when an earlier checkpoint evaluation is reused. ROOT signs derived inputs before the existing quality monitor compares them.

`evaluation_schedule` defaults to 128 reserved tasks, rotating deterministically and using the full reserved inventory every 24 rounds. It splits work into <=64-task chunks for the existing evaluator. Async queueing must preserve actual runtime/time/resource admission, reuse original signed requests and never overlap evaluator jobs on a busy GPU. No new hardware/source contract is assumed. `aggregate_evaluations` joins complete authenticated chunks into one fixed 128/750-task cohort so the monitor's minimum128 threshold is applied to the entire paired cohort. Missing chunks or before/after evidence stay pending; failures remain infrastructure unknown.

Integration still requires an operator async caller to locate exact original role records, authenticate/read the original durable adoption, obtain original signed evaluation exports, and ROOT-sign derived views/results after admission. No production process imports this adapter yet. The existing monitor may recommend a future training/publication hold for severe or repeated confirmed regression, but no current training step waits for evaluation and no automatic rollback or optimizer reset occurs. Full convergence remains unproven by a single training-margin increase or a 32-task diagnostic.
