The default-off CPU operator in `ops/automatic_owned_miner_cleanup.py` follows a ROOT-approved physical miner route and exact controller process. It checks the full pinned runtime and operator files before importing the cleanup adapter. It never launches a miner or changes an epoch, sampler, checkpoint, optimizer, reward, or verifier.

For each approved owned miner job, the adapter requires its original signed request, successful original report, actual terminal process observation, and a ROOT-signed ACK containing that original job/report. It PUTs this ACK into the private bucket and GETs every ACK byte back before disposal. The remote cleanup uses the existing complete authenticated checkpoint ownership receipt, single-link owner/inode checks and nonblocking checkpoint leases. Reports, logs, original requests, commitments, R2 objects and unowned directories remain intact. Any live process on the namespace defers disposal; failed jobs without a successful report remain explicitly deferred.

Historical directories without ownership receipts are not adopted. A complete terminal report cannot convert an arbitrary directory into owned disposable storage. A source change does not relabel model or optimizer evidence. Optimizer retention continues through its separate original durable-authority ACK protocol.

A separately ROOT-signed renewal authorization can make the timer durable across routine expiry and an identical controller restart. Renewal rechecks the exact config bytes, physical route, source allowlist, complete runtime, CPU operator files, controller unit bytes, launcher bytes and process argv before signing a fresh one-hour scope with the actual PID/ticks/invocation. A changed config, source, route, unit, launcher or argv requires a new explicit reviewed authorization; it cannot broaden ownership or adopt legacy directories. Renewal preserves original model/report ACKs and does not repeat completed disposal.
