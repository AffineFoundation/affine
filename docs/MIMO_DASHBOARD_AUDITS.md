# Closed-epoch audit counts

The MiMo dashboard previously displayed every captured group as unchecked and hardcoded accepted/rejected totals to zero. This prospective data-only change projects the original authenticated audit verdicts; it does not alter the website layout, grading, training admission, hourly rewards or diagnostic penalty deferrals.

The projection reads the existing role queue with SQLite `mode=ro` and `query_only`. It selects completed verification jobs only for closed epochs with a frozen population. The signed audit population must reconstruct successfully and match the exact published opening and coordinator dispatch. Existing `mimo_audit_bridge.admit_queue_reports` checks operator and worker signatures, admitted worker roles, job/source/runtime bindings, checkpoint, commitments, original queue report digest and token, full report structure, and closure/cutoff timing. Unauthenticated evidence is refused, not converted into a rejection.

Counts use distinct `(epoch, miner, batch digest)` identities internally. Retries do not add batches. A batch with both authenticated acceptance and rejection is separately counted as a conflict and remains unchecked in the three-way display; neither verdict is silently selected. Raw rejections remain rejections even when the independent reward writer temporarily defers their penalty. Missing evidence yields `null` totals and `audit_breakdown_available=false`; valid evidence with no completed audits produces a genuine zero and the frozen population remains unchecked. Partial availability includes separate `known_*` subtotals.

Only counts, availability flags and an aggregate evidence digest are exported. No miner identity, commitment, task, rollout, capability or open-epoch submission is added. Legacy history, training/evaluation records and incentive data retain their original paths and meaning.

Successful authentication is cached only in the dashboard process. Cache keys cover exact queue-row content, closed population/opening/dispatch bytes, authority, verifier roster and approved source/runtime mapping. Changed evidence is fully rechecked; failed evidence is not cached; disappeared rows and changed population bindings lose cached credit. Cold restart authenticates again. Newly seen reports use the complete existing admission path. These caches are performance aids, not signed evidence or durable trust.

The existing server's startup/poll `refresh()` computes the projection and atomically publishes a complete in-memory snapshot. HTTP handlers serve copies of that snapshot rather than authenticating audit evidence. A failed refresh preserves the previous complete snapshot and its original update timestamp. The existing export poll publishes the same completed snapshot; no additional service or queue is introduced.

Qualification includes duplicate/conflicting verdicts, unchanged and mutated evidence caches, changed dispatch binding, open-epoch exclusion, unchanged read-only queue bytes, unavailable-versus-zero semantics, and HTTP snapshot behavior. Before deployment, pin the new projection modules in the host configuration; keep the worker/scientific source and historical evidence immutable.
