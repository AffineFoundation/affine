The mixed-role prerequisite runs the native Tau2 agent and fixed auxiliary user
in separate operator-configured processes. The JSON transport bounds token and
float32 NPY geometry, authenticates startup descriptors and declared source
hashes, and retains activation handles inside each model worker. Its registry
accepts explicitly qualified runtimes rather than uploaded import paths.

The agent uses the approved 32K Qwen CUDA profile. The user retains the exact
fixed 135M weights under a separately qualified CUDA numerical profile. This
does not establish CPU/CUDA equivalence. Original user instructions, tools,
database and grader remain in the operator-native simulator. Auxiliary outputs
have false loss masks; only agent outputs are training targets.

Twenty-nine conformance controls cover descriptors, subprocess framing,
Mapping-style tokenizer outputs, proof handles, array headers, source admission,
worker cleanup and immutable source staging. These synthetic controls do not
replace real model qualification.

The immutable `state/native-tau2-common/mixed-cuda-1790865200` positive control
completed six model responses, reward 1, and separate fresh full-probability,
TOPLOC and original-native replay. Root authenticated 24 actual artifacts,
37,911,808 probability-array bytes and the source inventory. Its 31 agent tokens
are eligible; 97 auxiliary tokens are masked. This is curated target-model
computation, not proof of autonomous sampling. A negative control under the same
manifest also completed eleven model responses and reward 0. Root authenticated
its 34 actual artifacts, all 72 agent tokens and 111 masked auxiliary tokens.
The preference pair compares the first agent response at the same 6,944-token
prompt: 31 chosen tokens versus 14 rejected tokens. All later negative agent
responses were verified but are not included in that first-response pair. No
common storage epoch or training is claimed here.

`ops/stage_native_tau2_mixed_source.py` creates a new private source namespace.
Its operator-only inputs include qualified descriptors and task inventories;
the signing key and native private task data remain local. Generation and
verification are separate commands in `subnet.native_tau2_common_mixed_driver`.
Keep startup configuration, receipts and task data private. Publishing these
helpers does not deploy them or open miner admission.
