# Prospective trusted native evaluator

The existing ordinary evaluator generates a rollout, materializes full-vocabulary probability arrays and TOPLOC proofs, then independently verifies its own rollout. Its signed forced-v3 generation already uses KV caching. This proposal removes proof work only for an explicitly trusted operator-owned diagnostic job; miner verification and the default evaluation path stay unchanged.

`trusted_evaluation_policy` is absent by default. The exact signed opt-in is `trusted-native-generation-evaluation-v1`, trust scope `operator-owned-process-native-grader`, `proof_reverification=False`, and `sampling_policy=unchanged-signed-runtime`. Unknown/null or mixed policies fail admission. The new runtime module must appear in authenticated source pins. Fixed heldout indices/seeds/harness/caps, checkpoint authentication, original native environment/source and signed sampler binding stay unchanged.

The trusted path calls the existing `runtime.sample_output` directly. It decodes and grades the same response, without probability arrays, TOPLOC construction or self-reverification. Results explicitly say `verified=False`, `native_graded=True`, `proof_verification_performed=False`; they are not miner reward evidence. Task or model/grader exceptions produce separate infrastructure-failure rows, with aggregate mean reward/uncertainty absent when any task fails. They do not become wrong answers. A local per-task progress receipt records completed token counts and timings without becoming authority state.

Queue identity includes the explicit policy; legacy queue identity is unchanged when the field is absent. Original evaluation recovery compares the new signed policy field, preventing a pending full-proof job from being silently converted. The trusted cohort receives a separate diagnostic identity and assurance label. Historical verified records are not relabeled or mixed with trusted diagnostic scores.

Tiny CPU controls execute real cached-v3 and uncached generation, build and verify actual TOPLOC baseline proofs, then assert identical generated token hashes, grades and task hashes in the trusted path. Additional controls prohibit all probability/proof calls, enforce caps/session closure and heldout separation, reject wrong role/source/sampler/null/mixed policies, preserve legacy defaults, separate queue identities and keep infrastructure failures neutral. These are CPU scientific controls, not H200 qualification or proof of native MATH performance.

Production requires a new immutable complete source/native bootstrap qualification and actual honest H200 fixed-cohort comparison. Do not edit or reuse sealed9f/4109 archives. Do not restart, cancel, relabel or amend the original E19 evaluator. No sampling, model precision, attention backend or early-EOS semantic change is proposed here. Persistent cross-job model services and last-logit/eager-attention changes require separate source/profile controls; they are outside this change.
