# Explicit post-update, uncommitted recovery

`terminal-post-update-uncommitted-recovery-v1` is a separate ROOT-signed authorization to make one fresh attempt from the last durable optimizer parent. The failed original update occurred. An incomplete local or bucket candidate is never a parent, full checkpoint or durability ACK.

The declaration preserves the original signed request, physical terminal identity, failed export callchain/log digest, partial inventory digest, original output namespace and actual update count of one. It binds the same frozen unaudited learner objects, their original source/admissions, runtime versions, objective, parent publication and ordered inputs. It authorizes a distinct execution source, label, output namespace and immutable post-update reservation. Its complete execution science map permits reviewed worker/state transport and cache changes only; model, sampler and optimizer math pins remain original. Historical pre-update declarations and journals remain unchanged.

The operator must independently confirm original runner/child absence, failure, missing completed report/descriptor/publication, last durable public authority and controller handoff before dispatch. A constructor control is not GPU execution evidence. The large-envelope loader must explicitly admit this version; ordinary and upload budgets remain unchanged. Enable the reviewed train-recovery publication projection so a CPU upload does not inherit the train-only declaration. Finish-current mode must not open another epoch before legitimate closure.

`ops/retire_failed_training_candidate.py` is a CPU recovery-preflight callback, disabled without an executable ROOT-signed retirement grant. It authenticates the original request and exact partial inventory, full local hashes/inodes/ownership, pending catalogue and original cache lease. It requires full signed bucket readback receipts for every successfully uploaded shard, and, only if explicitly retiring failed shard zero, a separate evidence-object full readback for that file. The thirteen-only mode preserves failed shard zero locally. HEAD or PUT success is insufficient. Actual process/lease guards run before and during retirement. It durably records the original signed grant, failure and pending catalogue before any unlink, removes only the allowlisted original candidate/transfer bytes and pending marker, and leaves the checkpoint model, original request, failed terminal and publication history intact. An interrupted retirement resumes only the same signed grant and journal, revalidates remaining files and receipts, and accepts missing files only from that authenticated deletion allowlist. New files, changed grants and replaced inodes refuse. Completion is immutable and replay returns the same receipt; no second cleanup or partial-state adoption occurs.

No production recovery, retirement, optimizer14 publication or GPU qualification is implied by these prospective controls.
